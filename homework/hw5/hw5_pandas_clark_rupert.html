        vocalist = "both vocalists"

# creating column for line length in characters
hw5_df["length"] = hw5_df["line"].str.len()

# creating column checking if line contains profanity
profanity = ["fuck", "fucking", "fucked", "fucks", "shit", "ass", "asshole", 
             "damn", "damnit", "dammit", "piss", "hell", "bastard", "bitch"]

pat = r"\b(?:" + "|".join(word for word in profanity) + r")\b"
hw5_df["is_profane"] = hw5_df["line"].str.lower().str.contains(pat)

# creating column that contains a list of words in lowercase in each line
hw5_df["words"] = hw5_df["line"].str.lower().str.split(r"[\W_]+")

Conclusion

One row of the table stands for one line of lyrics in the songs in the sample set, all of which are by the doom/sludge metal crust punk band Dystopia. I threw out the vocalist labels on each line, because while they provide useful info for the vocalist column, after that was created there was no longer any use to them and they only cluttered the data. One thing I noticed on my new columns is that there was a lot less profanity in the songs in my sample set than I had thought, given Dystopia’s very angry and brash character as a band. I also noticed that, when finding the mean length of each line grouped by song with print(hw5_df.groupby("song")["length"].mean()), the song Socialized Death Sentence had the 2nd shortest lines on average out of the 5 songs in the sample set. This surprised me because the lines in the opening sample are pretty long, but I guess the short length of lines of lyrics compensated for that. I did use AI to to figure out how to check lines for profanity, but I asked it in-depth questions about how patterns worked and what each operation did for those I did not quite understand so I believe my use of it was justifiable.
